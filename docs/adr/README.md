# ADR（設計判断の記録）

重要な技術判断を、背景・選択肢・決定・理由とともに残す。

- ファイル名: `NNNN-<slug>.md`（例: `0001-harness-and-spec-workflow.md`）
- 一度書いた ADR は書き換えない。判断を覆すときは、新しい ADR を追加して古いものから参照する
- 機能の仕様は `docs/specs/` に書く。ADR は「なぜその技術や構成を選んだか」に絞る

## 書き方

```markdown
# NNNN. <判断の名前>

- 日付: YYYY-MM-DD
- 状態: 採用 / 置き換え（→ NNNN）

## 背景
## 選択肢
## 決定
## 理由と影響
```
