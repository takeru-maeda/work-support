### 見つけた不具合（計画書の P6 に足すもの）

- 作成を同時に 2 回送ると片方が 500（一意の制約を使って 1 回で「無ければ作る」にする）
- 初めてのユーザーの最初の `GET` の 404 が、毎回 `error_logs` に ERROR として残る
- 画面を移るたびに、ログインの確かめと設定の `GET` が走る（app-shell / auth と同じ原因）
- ログアウトとアカウントの削除で設定のストアを消さない
- 初期化に失敗すると、画面を開き直すまでスイッチを押せない。2 回目以降の失敗では前の値が残る
- テーマのちらつき（描画の前にクラスを付ける）

## 仕様レビュー（spec-reviewer）

- Major 1 件、Minor 9 件を受けて spec.md を直した。Major は、初期化に失敗したときに「設定は無いまま」と書いていたが、2 回目以降の失敗では前の値が残ること（AC-05）。Minor は、スイッチの表示の初期値、設定の取得の失敗で完了メールが送られないことと GAS の取り込みの扱い、初期化の間の読み込み中の表示、ストアを消す唯一の経路、`mutate` の書き方、AC-03 の 400 の具体例、`PUT` の 404 の記録、frontmatter の `code`
- ポストモーテムは `91bc403` の差分で確かめた（サインアップでの `createUserSettings` と失敗の `reportUiError`、設定の画面での取得と作成）。「`POST` は行があれば 200」は修正の前からあったので、対策の書き方を直した
- 事実の確認: 行が無いと `GET` と `PUT` が 404、`POST` を同時に 2 回送ると片方が 500、2 回目の `POST` は 200、真偽値でない値で 400 を、ローカルの Supabase で確かめた。画面を移るたびに確かめと設定の取得が走ることを `pnpm dev:local` で確かめた
