### 見つけた不具合（計画書の P6 に足すもの）

- まだミッションが無いユーザーが同時に 2 回保存すると、片方が 500（一意の制約の違反）。1 回の upsert にする
- 取得に失敗したときのエラーの文を、英語のまま画面に出す
- 入力が失われる経路: 保存中に「キャンセル」を押せ、その保存が失敗すると入力が戻らない。保存中も入力欄を操作でき、打ち足した文字は成功で捨てられる。編集中に取り直しが失敗すると入力欄がエラーの表示に置き換わる。画面を離れると入力が消える（下書きも確認も無い）

## 仕様レビュー（spec-reviewer）

- Major 2 件、Minor 9 件を受けて spec.md と記録を直した。Major はどちらも入力が失われる経路の書き漏れ（保存中のキャンセルと保存の失敗、画面の中にしか無い入力と取り直しの失敗）。Minor は、保存中の表示（ページ全体ではなく見出しの横のスピナー）、キャンセルで戻す先、「保存」を押せるかの比べ方、`content` に上限が無いこと、表示の空白の扱い、アカウントの削除で消えること、400 の応答の形、「テストとの対応」が既存のテストの範囲より広く書かれていたこと
- 400 の応答の形は、goals の確認で見た実際の応答（`{ data, error: [...], success: false }`）に合わせ、goals と weekly-report の仕様書の書き方もそろえた
- 事実の確認: ミッションが無いと `{ mission: null }`、初めての保存を同時に 2 回送ると片方が 500、空白だけの内容は保存され、空文字は 400 になることを、ローカルの Supabase で動かして確かめた
