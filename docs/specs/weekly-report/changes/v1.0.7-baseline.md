### 要確認

1. **土日の工数をどう扱うか**: 今は、合計・平均・案件別に土日の時間が入るのに、日別の行は月〜金だけ。平均の分母は月〜金の働いた日数なので、土日に働くと平均が大きくなる。旧ドキュメントは月〜金だけが対象。推奨: 土日に工数がある日だけ日別の行を出し、平均の分母にもその日を数える（合計と案件別は今のまま土日を含める）
2. **過去の週を出力したときの目標の数字**: 今は、目標ごとの進捗率と全体の平均に**今の値**を使い、期待値はどれか 1 つの目標の期間で**今日まで**の日数から出す。その週に出力するなら大きな差は無いが、過去の週を出すとその週の実際と違う。推奨: 週の終わり（日曜の終わり）時点の履歴の値を使い、期待値は目標ごとに週の終わりまでの日数で出して重みで平均する（旧ドキュメントの式）
3. **ミッションと学習状況を本文に入れるか**: 旧ドキュメントはミッションも出力するとしていたが、今は入らない（画面の上の編集欄からコピーする）。学習状況は中身の無い固定の欄。推奨: 今のまま（ミッションは別に貼る、学習状況は貼ったあとに手で書く）とし、仕様としてはっきり書く

### 見つけた不具合（計画書の P6 に足すもの）

- 日別の時間を丸めずに出すので、`3.3000000000000003h` のような長い小数になる
- 週の計算が実行環境のタイムゾーンに依存する（日本時間で動かすと日曜〜土曜になる）。週の境目は UTC の月曜 0:00（日本時間の月曜 9:00）
- 進捗の履歴を件数の上限なしで取る（`max_rows` を超えると古い履歴から切り捨てられ、週の始まりの値が 0 になる）
- 重みが同じ目標の並びと、期待値に使う目標が決まらない（DB の返す順）
- 進捗の履歴のクエリが `user_id` で絞っていない（目標の ID で絞っているので漏れはしないが、goals 側と守り方がそろっていない）
- 画面: 日付を変えても前の週の本文が残り、そのままコピーできる。コピーの失敗を知らせない。エラーの文を英語のまま出す

## 仕様レビュー（spec-reviewer）

- Major 2 件、Minor 11 件を受けて spec.md と記録を直した。Major は、履歴の無い目標の差分が今は goals の画面と週報で食い違っていること（この記録が「そろう」と誤って書いていた）と、期待値の式（日数の数え方、切り捨て、矢印の判定）がテストで決められる形になっていなかったこと（AC-10）。Minor は、目標ごとの値を丸めずに出すこと、`toFixed` の丸めの向き、全体の差分が丸めた値どうしの差で今の重みを使うこと、失敗時に `error_logs` に送ること、空の週の全文、日本時間で動かしたときのずれの向き、INV-3 が規約の例外であること、INV-2 が今も破れうること、AC-01 の「読み書き」、frontmatter の `code`
- 事実の確認: 空の週の全文、日別の時間の `3.3000000000000003h`、土日の工数が合計・平均・案件別に入り日別に出ないこと（月曜 1 時間、土日 30 時間で「平均：31h/日」）、日曜を選ぶとその日で終わる週になること、日本時間で動かすと週が日曜〜土曜にずれること、`date` の形が違えば 400 を、ローカルの Supabase で動かして確かめた
