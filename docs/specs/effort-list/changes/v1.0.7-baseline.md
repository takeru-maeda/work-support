### 要確認

1. **集計を絞り込んだ全体の合計にするか**: 今の「見積合計」「実績合計」「差分合計」は、表示中のページの行だけの合計で、1 ページの件数を変えると数字が変わる。見出しからは全体の合計に読める。推奨: API で絞り込んだ全体の合計を返し、画面はそれを出す（全体の合計が目的の画面なので）。P6 以降に改修の記録を通す

### 見つけた不具合（計画書の P6 に足すもの）

- 並べ替えの同じ値の行の順番が決まらず、ページ送りで重複や抜けが起きうる（最後に ID で並べる）
- 最後のページより先で 500（goals の過去の目標の検索と同じ）
- 絞り込みで案件を変えても、前に選んだタスクが残って 0 件になる
- 保存した件数や並べ替えの値を確かめず、壊れていると「クリア」するまで失敗が続く
- 読み込み中も、集計だけは前の条件の数字が出る
- 最初の取得に失敗すると、絞り込みが無ければ「工数データがまだ登録されていません」が出る
- 保存した日付の文字列が日付として読めないと、画面全体が落ちる（コードから。直すときに確かめる）
- 集計の小数の誤差で「-0.00h」「0.30h」が出る
- 表と集計で時間の小数の桁が違う

## 仕様レビュー（spec-reviewer）

- Major 1 件、Minor 11 件を受けて spec.md と記録を直した。Major は、読み込み中の表示が「最初の 1 回だけ」ではなくキャッシュの無い条件のたびに出ること（SWR 2.3.6 の `isLoading` の定義を確かめた）と、その間も集計だけは前の条件の数字が出る経路の書き漏れ。Minor は、「並べ替えなし」の保存と戻し、中立の印、候補が無いときの文言の条件、壊れた保存値の振る舞い、集計の小数の誤差、集計の差分の色、取得の失敗で「まだ登録されていません」が出ること、API の境界の値、0 件でページ送りを出さないこと、frontmatter の `code`、AC の分け方（AC-13、14 を足した）
- 事実の確認: 最後のページより先で 500、期間が両端を含むこと、開始日が終了日より後と `pageSize=501` が 400、差分の昇順で見積の無い行が最後になることを、ローカルの Supabase で動かして確かめた
